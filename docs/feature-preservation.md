# 功能保全与验收矩阵

本矩阵是人工场景的唯一来源和用户可见行为依据。适配流程、实现规则与降级门禁见 [宿主适配手册](host-adaptation-guide.md)，逐项证据、判据与状态见 [适配清单](host-adaptation-checklist.md)。

场景未执行时保持“待验收”，不以成员匹配、构建或安装成功代替；局部场景确认不代表整项功能或整个构建通过。每个功能域的生效条件与宿主接缝以手册对应章节为准。

## 1. 适用边界

版本、页面族、生产资格和各能力标志以 [host-profiles](../host-applemusic/src/main/resources/host-profiles/) 为准。“已登记”指 profile 允许能力接入，实际运行还受设置、设备形态、Android API 和契约解析结果限制。本矩阵维护共享要求，具体版本映射和验收记录分别保存在 profile 与任务记录中。

未登记组合保持不支持。新增版本应独立使用本矩阵验收，不能继承相邻构建的人工结果。旧 Activity 行为以既有档案和冻结夹具为依据；通用文档更新不替换冻结基线。

### 页面族的行为差异

| 项目 | Activity 页面族 | Fragment 页面族 |
|---|---|---|
| 设置 | 原生 PreferenceFragment / PreferenceScreen 和 Activity 结果桥 | 原生 ViewModel、分类/action 模型、Compose 和结果桥 |
| 双栏 | 原有播放器状态及资源布局接入，独立右歌词 | Fragment 事务与视图会话，左 SONG/QUEUE、独立右歌词 |
| 玻璃 | 手机及符合既有条件的双栏平板横屏；平板为底部导航/mini 组合 | 手机底导航；平板顶导航与独立底部 mini，玻璃与双栏开关独立 |
| 媒体组件 | 共享参考左栏、音量/输出及收起横条，保留原生底部动作 | 共享参考左栏与音量/输出，另按契约接入模式按钮和右下原生动作代理 |
| 视频 | 保留既有 Editorial 处理、预览及 Music Video 规则 | 原生视频策略；双栏外框与尺寸基准由当前视图会话统一维护 |
| 恢复 | 既有 Activity 生命周期和状态恢复 | view 身份、事务保存状态、封面/背景恢复和可关闭会话 |

两类路径复用左栏布局及音量/输出组件，各构建依据自己的 profile 选择接入。旧 Activity 保留原生底部动作；Fragment 另有 SONG/QUEUE 共用补充控件、关闭歌词居中、右下代理及有契约的模式按钮。私有成员、设置模型和附加界面的适用范围分别判定。

## 2. 共用歌词结果提交

[维护规则](host-adaptation-guide.md#lyrics-result-submission) · [证据清单](host-adaptation-checklist.md#lyrics-result-submission-checks)

手动、自动与 LLM 结果共用这条通道；查询、来源顺序与缓存策略在[歌词来源](#lyrics-sources)核对。

| 场景 | 预期 | 适用条件 |
|---|---|---|
| 首次自动补全（符合所选补全策略的官方可用 / 不可用歌曲） | 候选就绪且当前身份/安装上下文匹配后立即显示，无需重新进入歌词页 | 精确 profile 声明结果通道 |
| 播放中途替换 | 查询完成后即时生效，界面与内部文档一致，无旧歌词残留 | 同上 |
| 后台结果迟到（已切歌 / ViewModel 会话结束） | 不提交；视图重建后读取当前最新结果 | 同上 |
| 原生加载迟到返回 | 遵守来源优先级与文档质量规则，身份读取与显示一致 | 同上 |
| 加载入口未命中 / 结果先于附加到达 | 附加后仍绑定当前歌词页面并等待当前文档；上一首结果不被注入，当前结果到达即生效 | 同上 |
| 已确认当前文档后的空值或错误发布 | 已显示歌词不被清空；结果容器与派生索引仍指向当前文档 | 同上 |
| 安装入口以空 `SongInfoPtr` 进入 | 仅在同 Fragment、同 ViewModel、同请求、同播放身份且存在存活并 ID 匹配的当前文档或 ready replacement 时抑制一次，经既有结果通道补发；其余情况保持原生回退 | 同上 |
| 当前确无可用文档时的空信号 | 进入既有降级路径，界面与原生一致，不残留旧文档 | 同上 |
| 同一文档重复到达（含文本身份相同、对象不同） | 不重复提交，无重复刷新或高亮跳变 | 同上 |
| 手动条目与自动补全并存 | 手动结果优先；禁用歌曲不注入自动结果 | 同上 |
| 结果容器与派生索引一致（切歌 / 拖动进度 / 列表刷新） | 均使用新文档，无旧索引残留 | 同上 |
| 观察者抛异常后的提交失败 | 容器实际保存的文档与派生索引一致，未二次写入回滚；界面仍以原生观察者结果为准 | 同上 |
| 提交与切歌交叠 | 不写旧会话的选择与索引；新会话按自身文档重新构建 | 同上 |
| 索引复用与失效 | 模块预建后原生同指针索引不重复扫描一次；换歌、改写指针或会话结束后按实际文档重建 | 同上 |
| 原生 item 更新后重附加 | 宿主先更新自己的 item，模块随后附加当前 ViewModel，未主动改写 Fragment item | 同上 |
| 安装先于附加 | 未确认安装的同一指针在身份对齐后补发一次；确认安装后同一指针不重复提交 | 同上 |
| 歌词面板收起到 mini 后重新展开 | 已就绪的自定义歌词继续显示；同一 Fragment/ViewModel 复用或结果容器更换不会使界面回落到嵌入歌词 | 精确结果通道、身份一致且存在可用自定义文档 |
| 上传歌曲异步补全资料库实体，getId 改变而非零 persistentId 相同 | 配置仍命中原歌曲，实际提交指针绑定到宿主当前 ID；切歌返回、收放及迟到空结果不回退到嵌入文本 | 当前播放快照能证明身份关系 |
| 同一文档迁移实际提交 ID | 缓存逻辑 ID 不变，后台生成的独立原生指针能经过安装，不被同对象或同文档去重挡住；无主线程 TTML 重解析 | 候选保留原文且后台准备可用 |
| 资料库 ID 准备期间再次改变目标或切歌 | 进行中准备合并到最新目标，过期结果不覆盖当前歌曲；解析失败不循环重试 | 同上 |
| persistentId 为零、不可读或不同 | 不将另一 item 归入当前配置歌曲；原有切歌与过期结果保护保持 | 全部构建 |
| 同一 ViewModel 的 result 容器更换 | 附加和同 ID 请求刷新实际容器；同指针去重前读取其当前值，空值不当作旧确认 | 精确结果通道 |
| 空值、切歌或身份不匹配时无可用文档 | 不抑制原生空安装，不注入上一首或旧会话文档 | 同上 |
| 非空原生结果迟到 | 继续按既有来源优先级、文档质量和请求身份仲裁；空安装抑制不改写其参数 | 同上 |
| 重复 metadata 通知 | 同一 ID 的重复通知不打断领先请求；实际切歌才清除请求与待安装状态 | 同上 |
| Fragment 与请求身份不一致 | 暂缓模块替换；身份对齐后按新身份重新判定 | 同上 |
| 原生结果先于 Fragment native ID 对齐、空结果回调或新请求退役 | 同当前 canonical 请求、同当前 ViewModel 且显式加载已捕获该 raw ID 时，仅暂存一个存活结果，owner 对齐后经实际结果容器恢复；空/失活结果不占位，新请求、换 VM、切歌或关闭立即退役且不覆盖新请求 | 精确结果通道；实际时序按当前 profile 与运行证据确认 |
| 安装确认语义 | 安装调用无异常返回即结束待安装状态；不得当作界面已完整渲染 | 同上 |
| 合并 burst（同一主线程投递前的多次发布） | 只交付最后一个值；中间被覆盖的值不触发模块选择或额外结果通知 | 同上 |
| 缓存提前 / 落后 | 入队时缓存仍指向上一首、交付时已切到当前歌曲，仍按交付身份判定，不被旧缓存拒绝 | 同上 |
| 新 ViewModel 被拒后无后续生命周期回调 | 暂缓候选仍被重试匹配当前身份并附加 | 同上 |
| 候选 View 销毁或 ViewModel 更换 | 候选不被采用并在重试时清理；当前 ViewModel 清空后已跟踪 owner 一并清除并唤醒其余候选 | 同上 |
| 旧候选与活动 owner | 仅当被跟踪 owner 的 View 仍附着、其 ViewModel 字段仍是当前跟踪实例且 Fragment ID 匹配当前请求/身份时，同歌曲旧候选不替换它 | 同上 |
| 空 Pair 跨真实边界 | 交付时已跨真实请求/owner 边界则拒绝；同请求内的绑定恢复不误拒，已确认文档与派生索引不变 | 同上 |
| 契约缺失 / 提交异常 | 保留原生歌词与既有结果，降级原因可区分；不升级为全局观察或 LiveData 替换 | 同上 |
| 翻译、发音与其他歌词订阅者 | 不受结果提交影响，保持原有可用性与状态 | 同上 |

## 3. 歌词来源与候选准备

[维护规则](host-adaptation-guide.md#lyrics-sources) · [证据清单](host-adaptation-checklist.md#lyrics-sources-checks)

| 场景 | 预期 | 适用条件 |
|---|---|---|
| 多 ID / 快速切歌 / 切换队列 / 异步完成 | 当前播放对象、元数据转换与歌曲 ID 一致；旧异步结果不应用到新歌曲 | 全部构建 |
| 启用与禁用自定义歌词、连续切歌 | 增删改查、禁用优先级与重复注入抑制生效，无重复条目残留 | 自定义歌词接入 |
| 普通歌曲与无官方歌词歌曲 | 自定义歌词与原生指针有效性判断一致，两类歌曲都能正常显示 | 同上 |
| 缺词 / 非逐字 / 缺翻译 | 手动来源保留；两种模式均沿既有原生资格判断，不达标时按顺序查全部第三方 | 自动来源接入 |
| 网络失败 / 离线 | 保留当前可用歌词，无静默清空或旧结果回填 | 同上 |
| 手动与自动来源切换 | 手动条目与禁用状态优先于自动候选；切换后显示立即对应新来源 | 同上 |
| 自动来源顺序、旧配置与来源更新 | 新查询按用户顺序；Lunabeat 位于 AM 原生之前的旧顺序在读取、保存与运行时统一纠正，只将 Lunabeat 移到原生之后，其他来源相对顺序不变；缺项补齐、去重并过滤未知项；刷新只更新所记录的来源，手动及旧版受保护条目不被覆盖 | 同上 |
| 达标原生排在第一 / 中间 | 只查询原生前置来源，前置均未命中即采用原生 | 原生优先关闭 |
| 原生不达标或没有原生结果，原生项位于任意位置 | 仍按顺序查询全部第三方，包括原生之后的 Lunabeat，Lunabeat 仍启用；全部未命中时回退可用原生，不清空歌词 | 自动来源接入 |
| 自动缓存来源排位变化、原生迟到或查询中切换来源计划 | 缓存在所属 provider 位置生效，旧计划结果不提交；新自动保存项继续遵循选择策略，明确手动项优先 | 自动来源接入 |
| 缓存 / ETag / 退避 | 命中与再访问沿既有刷新策略，无重复注入；切歌或会话结束后旧结果不提交 | 同上 |
| 原生保留判断 | 无手动覆盖且原生优先开启时，达标原生直接保留；关闭时达标原生也遵循排序 | 同上 |
| 自动实时补全二级设置的来源排序 | 父页为导航入口；子页有总开关、原生优先和来源排序。按住右侧拖动柄上下拖动改序，松手保存，取消拖动不保存；柄外页面滚动正常，拖动期间列表滚动不与改序争用，无障碍上移/下移动作更新同一顺序；标题右上角“重置”只恢复 AMLL → AM-Lyrics → AM 原生 → Lunabeat，总开关和原生优先保持操作前状态；刷新停留本页，返回歌词管理 | 设置页可进入 |
| 原生优先开启或关闭时的来源排序与重置 | 开启时 AM 原生项隐藏，顺序仍保存为同一份完整顺序且不新增显隐配置；保存可见来源的新顺序后恢复隐藏占位：原位置能保持就保持，若 Lunabeat 已移到原位置之前则只把占位前插到 Lunabeat 之前，旧位置不阻止可见第三方互调且不重排其相对顺序。关闭优先、原生与 Lunabeat 同时可见时，两者仍不能互相越过，阻止后顺序不变；保存、重开与返回父页后可见顺序及完整顺序一致，完整顺序始终保持原生在 Lunabeat 之前 | 设置页可进入 |
| 手机/平板排序区标题及资格说明 | 排序标题区沿用原有紧凑行样式，不额外设最小高度或居中标题行，保留右上角“重置”和原有标题；标题、说明、来源文字及右侧拖动柄的左右内容边界对齐上方两个开关；原生优先开/关均明确原生须满足逐字及外语译文条件，关闭原生优先时提示 Lunabeat 必须排在 AM 原生之后 | 设置页可进入 |

## 4. LLM 原生歌词翻译

[维护规则](host-adaptation-guide.md#llm-lyrics-fallback) · [证据清单](host-adaptation-checklist.md#llm-lyrics-fallback-checks)

LLM 仅增强来源选择最终采用的 AM 原生歌词，结果仍经[共用结果提交](#lyrics-result-submission)。输入与输出格式、客户端协议在手册维护。

| 场景 | 预期 | 适用条件 |
|---|---|---|
| 所需第三方查询均未命中，回退外文 AM 原生 Line/Word 且无原生译文 | 后台翻译完成后直接显示简体中文译文，原时间轴保持；原生不达标时不会跳过后置来源提前翻译 | LLM 与上级开关均开启 |
| 采用第三方或手动歌词，缺少译文 | 不调用 LLM，也不采用原生对应的 LLM 缓存 | 全部 |
| Word 文档缺少根 `xml:lang` | 不调用 LLM；自动查源仍按所选策略判断 | 逐字文档 |
| 外文逐行文档正文缺少 `itunes:key`，或只有空 `<translations>` 占位 | 正常翻译并写入副本；正文补齐稳定唯一标识，已有 key、原文、时间轴与声部不变；输出只有一个 `<translations>`；再次播放命中缓存不重复请求 | 逐行文档 |
| 原生正文 key 自身重复、无法唯一对应行 | 保守拒绝，不调用接口，保留原歌词 | 逐行文档 |
| 中文简繁体 / 地区标签、已有任意语言原生译文、纯文本 | 不调用 LLM，也不复用已存 LLM 译文 | 全部 |
| 外文夹中文、日文汉字、重复句、和声与音译 | 中文行保持原样；日文可翻译；各行对应与原时间轴完整 | 全部 |
| 主唱与和声同段、纯和声、多段和声、和声先于主唱，或各声部语言不同 | 分别翻译对应声部，中文声部保持；每段仅一个 `text for`，和声使用 TTML 命名空间的 `x-bg` 子节点，缺 key 时主唱与和声共用一次补齐的 key；原正文与时间轴不变 | 采用原生且无原生翻译 |
| 升级声部提取或写回格式后再次播放 | 提示词/缓存版本不匹配的旧译文失效，符合原生/来源资格后重新生成；缓存仍最多 100 首，不写入自定义歌词 | 有旧版 LLM 缓存 |
| 有 LLM 缓存后再次播放，采用第三方或原生已有译文 | 使用所选来源结果，LLM 缓存不抢先 | 全部 |
| 有 LLM 缓存，采用原生且当前输入符合翻译资格 | 复用当前配置与原文匹配的译文，无重复翻译请求；自定义歌词列表无新增项 | 全部 |
| 原文、接口或模型更改 | 不复用旧配置或旧原文的翻译结果 | 全部 |
| 超时、错误 JSON、行数不符、接口失败 | 保留原歌词，本次播放不持续重试，不切换其他服务 | 全部 |
| 等待来源、资格跳过、请求失败、原生解析失败 | 正常跳过保持安静，失败保留原歌词；无逐阶段排查日志 | 全部 |
| 思考参数不受接口支持 | 连接测试显示对应错误，不移除参数后以服务默认模式重试 | 当前思考模式的请求 |
| 思考开关开/关、保存重开、翻译或测试中切换 | 默认和旧配置关闭，显式选择保存；翻译/测试模式一致，不混用缓存，旧任务/测试迟到结果不提交 | 可配置LLM |
| 翻译中切歌、快速往返、关闭开关或结束会话 | 不串歌、不注入过期结果，旧任务取消 | 全部 |
| 超过 100 首并重新命中旧项 | 按最近使用淘汰，磁盘条目保持上限 | 全部 |
| 重建、暂停重开、字体 / 模糊 / CJK 及原生翻译开关 | 使用现有原生结果链，各订阅者与视图生命周期保持正常 | 全部 |
| 打开 LLM 二级设置 | 自定义歌词页只保留导航入口；开关、地址、密钥、模型、思考与测试连接集中在二级页 | 设置页可进入 |
| 编辑后刷新、标题栏或系统返回 | 编辑不跳回首页，刷新仍停留当前二级页；返回先回自定义歌词页再回设置首页，父页搜索状态保留 | 同上 |
| 长 API 地址 / 长模型名 / 已填密钥，手机与平板、深浅主题 | 字段标题与箭头始终可见，值在下方单行省略，点击编辑可见完整值；密钥遮蔽；地址/密钥/模型/思考图标分别表达地球/钥匙/芯片/气泡，其他图标尺寸不变 | 同上 |
| 翻译关闭或上级开关未开启 | API 配置与测试连接仍可用；翻译开关按既有依赖禁用并给出简短提示 | 同上 |
